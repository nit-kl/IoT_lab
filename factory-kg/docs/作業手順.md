# 作業手順（factory-kg）

工場ナレッジグラフを作り、AWS に公開し、ローカルビューアで見て、最後に片付けるまでの手順。
上から順に進めれば、初めての人でも 1 時間ほどで一通り確認できる。

- 設計・方針・懸念点: [実現方針.md](実現方針.md)
- コマンドやファイルの説明: [factory-kg/README.md](../README.md)
- replay（工場 CSV リプレイ基盤）の手順: [factory-replay/docs/作業手順.md](../../factory-replay/docs/作業手順.md)

コマンドはすべて **PowerShell で `factory-kg` フォルダから** 実行する。

| 章 | 内容 | AWS | 所要時間 |
|---|---|---|---|
| 0 | 事前準備（初回のみ） | 不要 | 5 分 |
| 1 | 毎回の準備 | — | 1 分 |
| 2 | グラフを作る（オントロジー・TTL・検証） | 不要 | 5 分 |
| 3 | AWS に公開する（SPARQL エンドポイント） | 使う | 10 分 |
| 4 | ローカルビューアで見る | 使う | 10 分 |
| 5 | グラフを更新する（運用） | 使う | 10 分 |
| 6 | （任意）大きいグラフの読み込み時間 | 使う | 10 分 |
| 7 | 後片付け | 使う | 10 分 |

replay の環境（`xcp-factory-<owner>`）は、3 章以降で「グラフに書く API の URL」と「ビューアに出す値」に使う。
なくても 2〜4 章は動く（URL は仮になり、値は「取得できません」と表示される）。

## 0. 事前準備（初回のみ）

factory-replay とは別の仮想環境を作る（RDF 用のライブラリを入れるため）。

```powershell
cd factory-kg
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt      # rdflib, pyshacl, pyoxigraph, boto3[crt]
```

- `このシステムではスクリプトの実行が無効…` と出たら `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を一度実行
- ビューア（4 章）は Web ブラウザで開く。画面のライブラリは cdn.jsdelivr.net から読むのでインターネット接続が必要

## 1. 毎回の準備

```powershell
cd factory-kg
.\.venv\Scripts\Activate.ps1
aws login                            # 2 章だけなら不要
$owner = "<owner>"                   # 自分の名前（例: kojima）
```

## 4. ローカルビューアで見る

ビューアは **この PC だけで動く小さなサーバー** で、aws login の認証情報で KG の SPARQL と replay の API に署名して中継する。

```powershell
python tools/kg_viewer.py --owner $owner        # ブラウザで http://127.0.0.1:8765/ が開く
```

- 起動時に `ナレッジグラフ: https://…`、`replay の API: https://…`、`ビューア: http://127.0.0.1:8765/` と表示される
- **使い終わったら、ブラウザのタブを閉じてから、ターミナルで Ctrl+C で止める**（表示したままだと、1 分ごとの自動更新が replay の DB を起こし続ける）
- 値の動きを見たいときは、replay を早送りしておく（factory-replay で `python tools/cli.py --owner <owner> reset --speed 720`。約 2 分で 1 日分）

### 確認 4-1：グラフが表示されること

| 場所 | 期待する結果 |
|---|---|
| 上部 | `replay: done（21,600 行）`（再生中なら `replay: 再生中 xx%（CSV …、60 倍速）`）、`KG: 900 トリプル` |
| 左のグラフ | 上から サンプル工場 → サンプル工場 サイト → 製造エリア → ライン A → 設備 5 つ（COMP-01・CONV-01・ENV-01・CNC-01・PRESS-01） |
| 設備の縁の色 | CNC-01・PRESS-01 は稼働状態で色が付く（灰色 = 停止、緑 = 稼働、赤 = 異常停止）。COMP・CONV・ENV は稼働状態を持たないので枠だけ |
| 下の凡例 | 工場〜計測項目の色、設備の縁の色の意味 |

### 確認 4-2：設備を選ぶ

**CNC-01** をクリックする（または検索欄に `CNC-01` と入れて Enter）。

- グラフ: CNC-01 の下に計測項目 4 つ（主軸負荷・主軸回転数・稼働状態・加工数）が展開される。もう一度クリックすると畳む
- 右の詳細:
  - `稼働状態` のバッジ（例: `停止（0）`）と、その時点の CSV 上の時刻
  - 計測項目ごとの最新値（`0 %`、`0 rev/min`、`停止（0）`、`0 #` など。値はリプレイの位置で変わる）
  - 「ナレッジグラフ上の関係」: 種類が `計測対象（sosa:FeatureOfInterest）` と `生産設備（s4inma:ProductionEquipment）`、
    `分類` が `CNC 加工機`、`計測項目を持つ` が 4 行。右端の「記述のあるグラフ」が `インスタンス`

### 確認 4-3：計測項目を選ぶ（値と時系列）

CNC-01 の **主軸負荷** をクリックする（または `http://127.0.0.1:8765/#q=主軸負荷` を開く）。

- 最新値（大きな数字と単位 `%（パーセント）`）、CSV 上の時刻と反映時刻
- 時系列グラフ: 横軸が CSV 上の時刻。リプレイが終わってから 60 分以内なら 1 日分が表示され、14:00 から負荷が 90% 超まで上がって 0 に落ちる（チョコ停）様子が見える。
  範囲外なら「この範囲のデータはありません」→ 上の「時系列」を `直近 24 時間` などに広げる
- 「値の取得方法」: 最新値・時系列の URL が replay の Function URL で、グラフ（TTL）に書かれた URL・テンプレートから作られている
- **PRESS-01 の稼働状態** を選ぶと、値が `停止（0）` のようにコード表の意味で表示され、時系列は 停止 / 稼働 / 異常停止 の階段状のグラフになる

### 確認 4-4：検索・絞り込み・SPARQL・自動更新

| 操作 | 期待する結果 |
|---|---|
| 検索欄に `コンプレッサ` → Enter | COMP-01 が選ばれる |
| 分類を `CNC 加工機` | CNC-01 以外の設備が薄くなる |
| 下の「SPARQL を直接実行する」を開いて「実行」 | 設備 ID と日本語名の表（5 行）。更新文（INSERT など）はエラーになる |
| replay の再生中に画面を表示したままにする | 1 分ごとに上部の %・設備の縁の色・詳細の値が変わる |

終わったらタブを閉じて、ターミナルで **Ctrl+C**（`停止しました`）。

## 5. グラフを更新する（運用）

グラフの更新は **TTL を作り直して公開する** ことだけで行う（DB への直接の書き込み・画面からの編集はしない）。
公開は SHACL 検証に通ったときだけ行われ、公開後は SPARQL エンドポイントが新しい版を使っていることまで確認される。

| 変えたいもの | 手順 |
|---|---|
| 設備・ラインの増減（replay に流す CSV を変えた） | replay に新しい CSV を流す → `python tools/generate_ttl.py --owner $owner` → `python tools/publish_ttl.py --owner $owner` |
| 名前・分類・単位の対応 | `tools/generate_ttl.py` のカタログ（`EQUIPMENT_TYPES` / `METRICS` / `UNITS`）や `ontology/*.ttl` を直す → 単位・標準の語を増やしたら `python tools/vocab.py` → 生成 → 公開。直したファイルは Git にコミット |
| replay を作り直した（API の URL が変わった） | `python aws/setup_aws.py --owner $owner`（replay の新しい URL でグラフを作り直して公開する） |
| 公開したグラフを 1 つ前に戻す | `python tools/publish_ttl.py --owner $owner --rollback`（1 つ前の版をコピーして最新にする。もう一度実行すると元に戻る） |

### 確認 5-1：更新・ロールバック・不正な TTL の拒否

ラインを 3 本にしたグラフを公開して反映を確かめ、元に戻す。

```powershell
python ../factory-replay/tools/generate_csv.py --lines 3 --interval 30m --out "$env:TEMP\3lines.csv"
python tools/generate_ttl.py --csv "$env:TEMP\3lines.csv" --owner $owner    # URL は replay のまま、設備は 3 ライン分
python tools/publish_ttl.py --owner $owner                                  # … 1300 トリプル
python tools/sparql.py --owner $owner -e "SELECT (COUNT(?e) AS ?equipment) WHERE { ?e xf:equipmentId ?id }"   # 15
python tools/publish_ttl.py --owner $owner --rollback                       # … 900 トリプル
```

不正な TTL が公開されないこと:

```powershell
python tools/generate_ttl.py --owner $owner
# build/instances.ttl の「qudt:hasUnit unit:PERCENT ;」の行を 1 つ消して保存してから:
python tools/publish_ttl.py --owner $owner
```

- `SHACL 検証で違反が 1 件あるため公開しません:` と、どの計測項目に単位がないかが表示され、公開中のグラフは変わらない
- 確認後は `python tools/generate_ttl.py --owner $owner` で作り直す

## 6. （任意）大きいグラフの読み込み時間

```powershell
python tools/bench_load.py                                          # この PC
python tools/bench_load.py --owner $owner --sizes 10000 100000      # AWS の Lambda（512 MB）
```

- Lambda で測るときは、公開中のグラフを一時的に合成グラフに差し替えて測り、最後に元に戻す（`元のグラフに戻しました（900 トリプル、ETag 一致: True）`）
- 100 万トリプル（N-Quads 約 216 MB）は 512 MB の Lambda に載らない。測るときは
  `python aws/setup_aws.py --owner $owner --memory 2048 --skip-publish` → `bench_load.py --owner $owner --sizes 1000000` → 終わったら `--memory 512` に戻す
- 実測（2026-10-24）: Lambda 512 MB で 1 万トリプル 98 ms・10 万 1.3 秒、2048 MB で 10 万 0.4 秒・100 万 4.6 秒（S3 からの取得込みで 8.5 秒）。
  PC では 1 万 21 ms・10 万 227 ms・100 万 2.6 秒

## 7. 後片付け

### KG だけ片付ける

```powershell
python aws/teardown_aws.py --owner $owner       # yes と入力。replay の環境には触れない
```

次のように出れば完了（スタック・グラフ用とコード用の S3 バケット・Lambda・ログが残っていないことを確認している）。

```
残っているリソースを確認しています（xcp-factorykg-<owner>）...
残っているリソースはありません（課金されるものは残っていません）
```

- 削除せずに確認だけ: `python aws/teardown_aws.py --owner $owner --check`
- ビューアが起動したままなら先に Ctrl+C で止める（止めなくても課金はないが、replay を片付けた後は値が取れなくなるだけ）

### replay も片付ける

KG を片付けた後で、replay の手順（[factory-replay/docs/作業手順.md](../../factory-replay/docs/作業手順.md) の「8. 後片付け」）に従う:

```powershell
cd ..\factory-replay
.\.venv\Scripts\Activate.ps1
python aws/teardown_aws.py --owner $owner
```

KG を残したまま replay だけを片付けてもよい（グラフ・SPARQL・ビューアのグラフ表示は動き、値の欄が「取得できません」になる）。
replay を作り直したら、5 章のとおり KG の `setup_aws.py` を再実行して URL を更新する。

## うまくいかないとき

### グラフを作る

| 症状 | 原因と対処 |
|---|---|
| `カタログにないものがあります` | CSV / API に、カタログ（`tools/generate_ttl.py` の `EQUIPMENT_TYPES` / `METRICS` / `UNITS`）にない設備・計測項目・単位がある。カタログに追記して再生成する（単位を追加したら `python tools/vocab.py` も） |
| `公式の定義にない IRI があります` | 手書きの TTL か生成した TTL に、標準語彙に存在しない語がある。綴りを直す（標準の更新で語がなくなった場合は `python tools/vocab.py --refresh` で取り直して確認） |
| `SHACL 検証: 違反 …` | 表示された対象とメッセージを見て、カタログか手書きの TTL を直して再生成する |
| `vocab.py` で取得に失敗する | ネットワーク・プロキシを確認する。取得できた分は `.cache/vocab/` に残る |
| `--owner` 指定で `replay の環境（xcp-factory-<owner>）に接続できません` | replay の環境がない（`Stack … does not exist`）か、aws login が切れている。`--csv` で生成するか、replay を作る・ログインし直す |
| replay から生成すると 503 で止まる | replay の DB が一時停止から再開中。30 秒ほど待って再実行する |
| `MissingDependencyException ... botocore[crt]` | `pip install -r requirements.txt` をやり直す |

### AWS（SPARQL エンドポイント）

| 症状 | 原因と対処 |
|---|---|
| `setup_aws.py` で `pyoxigraph … の arm64 用配布物が見つかりません` | ローカルの pyoxigraph の版に Lambda 用の配布物がない。`pip install "pyoxigraph==0.5.13"` など配布物のある版に合わせる |
| スタックの作成に失敗する | `aws cloudformation describe-events --stack-name xcp-factorykg-<owner>` で原因を確認し、`teardown_aws.py` で片付けてから再実行する |
| SPARQL が 503（`グラフが未公開です`） | まだ公開していない。`python tools/publish_ttl.py --owner $owner` |
| SPARQL が 413（`結果が大きすぎます`） | 応答が 5.5 MB を超えた。`LIMIT` を付ける |
| SPARQL が 403 | CLI なら aws login のやり直し、Postman なら `postman.py env` で Environment を作り直す |
| `publish_ttl.py` で `Lambda が新しいグラフを読み込んでいません` | 公開直後に別の版が上がった可能性。`python tools/sparql.py --owner $owner --status` の `etag` を確認し、もう一度 publish する |
| replay を作り直したら最新値の URL が古いまま | `python aws/setup_aws.py --owner $owner`（replay の新しい URL でグラフを作り直して公開する）。SHACL が「URL の更新漏れ」を検出するのは、グラフの中の URL どうしの食い違いだけ |

### ビューア

| 症状 | 原因と対処 |
|---|---|
| 画面が真っ白・グラフが出ない | インターネットにつながっているか（ライブラリを cdn.jsdelivr.net から読む）。右下に赤いメッセージが出ていればその内容を確認 |
| `replay: 取得できません`・値が「取得できません」 | replay の環境がない、または DB の再開中。replay を作るか、30 秒ほど待って「更新」。グラフ自体は表示される |
| `HTTP 403` | aws login が切れている。ビューアを Ctrl+C で止め、`aws login` してから起動し直す |
| `Address already in use` などで起動しない | 8765 番ポートを使っている。`--port 9000` などで起動する |
| 時系列が「この範囲のデータはありません」 | 反映時刻で見ているため、リプレイが終わってから時間がたつと範囲外になる。「時系列」を広げるか、replay で `reset --speed 720` |
