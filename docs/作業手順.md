# 作業手順（AWS での動作確認）

`factory-replay` を自分の AWS 環境で動かして確認するための手順。ステップが進むたびに追記する。
方針は [実現方針.md](実現方針.md)、各スクリプトの詳細は [factory-replay/README.md](../factory-replay/README.md) を参照。

以下のコマンドは PowerShell で、`factory-replay` フォルダで実行する前提。
`<owner>` は自分の名前（英小文字で始まる英小文字・数字 2〜16 文字。例: `kojima`）に置き換える。

## 0. 事前準備（初回のみ）

| 必要なもの | 確認コマンド |
|---|---|
| Python 3.10 以上 | `python --version` |
| AWS CLI v2 | `aws --version` |

PC 全体の Python を汚さないよう、`factory-replay` 専用の仮想環境（venv）を作ってその中にライブラリを入れる。

```powershell
cd factory-replay
python -m venv .venv                 # 仮想環境を作る（初回のみ）
.\.venv\Scripts\Activate.ps1         # 有効化。プロンプトの先頭に (.venv) と出れば OK
pip install -r requirements.txt
```

- 以降の手順は、**毎回ターミナルを開いたら `.\.venv\Scripts\Activate.ps1` で有効化してから** 実行する
- `このシステムではスクリプトの実行が無効になっているため…` と出たら、次を一度だけ実行してから有効化し直す

  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

- 終わるときは `deactivate`。`.venv` フォルダは Git 管理外

## 1. AWS にログインする

```powershell
aws login
aws sts get-caller-identity          # 自分のアカウント・ユーザーが表示されれば OK
aws configure get region             # ap-northeast-1 であること
```

- `Your session has expired` と出たら、もう一度 `aws login` する
- リージョンが違う場合は、各スクリプトに `--region ap-northeast-1` を付ける（既定は ap-northeast-1）

## 2. ステップ 1：サンプル CSV を確認する（AWS 不要）

```powershell
python tools/generate_csv.py --out "$env:TEMP\check.csv"
```

- `21,600 行 / 1.3 MB` と表示されること
- 同梱の `data/factory_sample.csv` と同じ内容になること（`fc.exe data\factory_sample.csv "$env:TEMP\check.csv"` で差分なし）

## 3. ステップ 2：AWS 環境を作成する

```powershell
python aws/setup_aws.py --owner <owner>
```

- 初回は Aurora の作成に **10〜15 分** かかる
- 最後に次のように表示されれば成功

  ```
  スタックの作成が完了しました
  DB に接続しています（一時停止中なら再開まで数十秒かかります）...
  テーブルを作成しました: staging_readings, readings, replay_state

  スタック名 : xcp-factory-<owner>
  バケット   : xcp-factory-<owner>-data-<アカウントID>
  クラスター : arn:aws:rds:ap-northeast-1:<アカウントID>:cluster:xcp-factory-<owner>
  ```

- もう一度実行すると「スタックに変更はありません」と出て、テーブル作成だけやり直す（中身は消えない）

### 確認 1：コンソールで作成物を見る

| 画面 | 確認すること |
|---|---|
| CloudFormation > スタック | `xcp-factory-<owner>` が `CREATE_COMPLETE` |
| RDS > データベース | クラスター `xcp-factory-<owner>` があり、インスタンスが `db.serverless` |
| RDS > クラスター > 設定 | 容量が 0〜4 ACU、自動一時停止が有効、RDS Data API が有効 |
| S3 | バケット `xcp-factory-<owner>-data-<アカウントID>` がある |
| タグ | 各リソースに `Project=xcp-factory`, `Owner=<owner>` が付いている |

### 確認 2：テーブルができていることを SQL で見る

スタックの出力を変数に入れてから、Data API で SQL を実行する。

```powershell
$stack = "xcp-factory-<owner>"
$cluster = aws cloudformation describe-stacks --stack-name $stack --query "Stacks[0].Outputs[?OutputKey=='ClusterArn'].OutputValue" --output text
$secret  = aws cloudformation describe-stacks --stack-name $stack --query "Stacks[0].Outputs[?OutputKey=='SecretArn'].OutputValue" --output text

function sql($q) {
  aws rds-data execute-statement --resource-arn $cluster --secret-arn $secret --database factory `
    --format-records-as JSON --query formattedRecords --output text --sql $q
}

sql "SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' ORDER BY 1"
sql "SELECT extname FROM pg_extension ORDER BY 1"
sql "SELECT * FROM replay_state"
```

| SQL | 期待する結果 |
|---|---|
| テーブル一覧 | `readings`, `replay_state`, `staging_readings` |
| 拡張一覧 | `aws_commons`, `aws_s3`, `plpgsql` を含む |
| `replay_state` | 1 行だけで、`status` が `idle`、`speed` が `60` |

- `DatabaseResumingException` が出たら DB が一時停止から再開中。数十秒待って再実行する
- コンソールの RDS > クエリエディタ（データベース `factory`、認証情報はクラスターのシークレットを選択）でも同じ SQL を実行できる

### 確認 3：使っていない間に一時停止すること

最後の SQL から **5 分以上** 何もしないで待ち、CloudWatch > メトリクス > RDS で
クラスター `xcp-factory-<owner>` の `ServerlessDatabaseCapacity` が **0** になっていることを確認する。
0 の間は ACU の課金がかからない（ストレージ代のみ）。

## 4. 後片付け

検証を終えるとき、またはやり直したいときに実行する。DB の中身と S3 の CSV はすべて消える。

```powershell
python aws/teardown_aws.py --owner <owner>     # yes と入力すると削除開始（10 分ほど）
```

- 「削除が完了しました」と出たら、CloudFormation にスタックが残っていないこと、RDS・S3 に `xcp-factory-<owner>` が残っていないことを確認する

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `Your session has expired` / `Unable to locate credentials` | `aws login` をやり直す |
| `MissingDependencyException: ... pip install "botocore[crt]"` | `aws login` の認証情報を使うための追加ライブラリが入っていない。`pip install -r requirements.txt` をやり直す（`boto3[crt]` が入る） |
| `ModuleNotFoundError: No module named 'boto3'` | 仮想環境が有効になっていない。`.\.venv\Scripts\Activate.ps1` を実行する（初回なら「0. 事前準備」から） |
| `--owner は英小文字で始まる…` | 名前のルール違反。英小文字で始め、英小文字・数字のみ 2〜16 文字にする |
| `スタックの作成に失敗しました` | `aws cloudformation describe-events --stack-name xcp-factory-<owner>` で失敗したリソースと理由を確認。ロールバック完了後に `teardown_aws.py` で消してから再実行する |
| 失敗理由が `The maximum number of VPCs has been reached` | リージョンの VPC 上限（既定 5）。不要な VPC を消すか、Service Quotas で上限緩和を申請する |
| 失敗理由に `already exists` | 同名のリソースが残っている。`teardown_aws.py` を実行してから再作成する |
| 失敗理由に `MinCapacity` / `SecondsUntilAutoPause` の非対応 | 既定のエンジンバージョンが 0 ACU 非対応の可能性。報告してほしい（テンプレートでバージョンを指定する） |
| `DatabaseResumingException` が続く | 一時停止からの再開待ち。1 分ほど待って再実行する |
