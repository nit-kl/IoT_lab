# デモ環境の準備手順(オンプレ模擬)

手元の PC の WSL に最新の Ubuntu と Docker Engine を入れ、その上で Oracle を動かして、模擬の工場データを入れるまでの手順です。AWS の費用はかかりません。
所要時間は 45〜90 分です(大半はダウンロードの待ち時間)。

> Windows 11 Home、Ubuntu 26.04、Oracle 23.26(`latest-lite`)で動作を確認済みです。問題が出たら、手順の番号とエラーの全文を共有してください。パスワードは伏せてください。

## 全体の構成

```text
Windows                              WSL(Ubuntu 26.04)
 投入プログラム(Python)                Docker Engine
   └─ 127.0.0.1:1521 ─────────────────→ Oracle コンテナ
```

コマンドを実行する場所が 2 つあります。各手順の見出しの **[PowerShell]** と **[Ubuntu]** を確認してください。

| 必要なもの | 目安 |
|---|---|
| Windows | Windows 10/11(Home 可) |
| メモリ | 8GB 以上 |
| ディスク空き | 20GB 以上 |
| Python | Windows 側に 3.13 |

## 1. WSL を更新する [PowerShell]

1. WSL を更新します。

   ```powershell
   wsl --update
   wsl --version
   ```

2. 更新を反映します。**既存の WSL 環境もすべて止まる**ので、作業中のものがあれば先に閉じてください。

   ```powershell
   wsl --shutdown
   ```

## 2. Ubuntu を入れる [PowerShell]

1. 入れられる版を確認します。

   ```powershell
   wsl --list --online
   ```

2. 一覧に `Ubuntu-26.04` があれば、それを入れます。

   ```powershell
   wsl --install -d Ubuntu-26.04
   ```

   一覧にない場合は `wsl --install -d Ubuntu` を実行し、手順 3 の版の確認で 26.04 以降(26.10 も可)であることを確かめます。以降の `Ubuntu-26.04` は、実際に入った名前に読み替えてください。

3. 初回はユーザー名とパスワードを聞かれるので、設定します。これは Ubuntu の `sudo` 用で、Oracle のパスワードとは別です。

   Ubuntu 26.04 は執筆時点の最新の LTS(長期サポート版)です。26.10 のほうが新しいものの、サポート期間が短いので LTS を使います。既存の `Ubuntu-20.04` には触りません。

## 3. Ubuntu を確認する [Ubuntu]

別の Ubuntu が開かないよう、PowerShell から名前を指定して開きます。

```powershell
wsl -d Ubuntu-26.04
```

1. 版と systemd を確認します。

   ```bash
   . /etc/os-release && echo "$PRETTY_NAME"
   systemctl is-system-running
   ```

2. `systemctl` が `running` か `degraded` なら次へ進みます。それ以外なら systemd を有効にします。

   ```bash
   printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf
   ```

   その後 `exit` し、PowerShell で `wsl --terminate Ubuntu-26.04` を実行して、開き直します。

## 4. Docker Engine を入れる [Ubuntu]

[Docker の公式手順](https://docs.docker.com/engine/install/ubuntu/)に沿っています。

1. Docker の公式リポジトリを登録します。

   ```bash
   sudo apt update
   sudo apt install -y ca-certificates curl
   sudo install -m 0755 -d /etc/apt/keyrings
   sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
   sudo chmod a+r /etc/apt/keyrings/docker.asc
   printf '%s\n' \
     'Types: deb' \
     'URIs: https://download.docker.com/linux/ubuntu' \
     "Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")" \
     'Components: stable' \
     "Architectures: $(dpkg --print-architecture)" \
     'Signed-By: /etc/apt/keyrings/docker.asc' \
     | sudo tee /etc/apt/sources.list.d/docker.sources
   sudo apt update
   ```

2. Docker Engine を入れ、`sudo` なしで使えるようにします。

   ```bash
   sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
   sudo usermod -aG docker "$USER"
   exit
   ```

3. PowerShell で `wsl --terminate Ubuntu-26.04` を実行し、`wsl -d Ubuntu-26.04` で開き直して確認します。

   ```bash
   command -v docker
   docker run --rm hello-world
   ```

   `command -v docker` は `/usr/bin/docker` になるはずです。`/mnt/` で始まるパスや `docker-desktop` を含むパスなら、Docker Desktop のものが使われています。Docker Desktop の Settings > Resources > WSL Integration で `Ubuntu-26.04` をオフにしてください。

## 5. Oracle を起動する [Ubuntu]

1. Oracle の管理者パスワードを決めます。**英字で始まる 12 文字以上の英数字と `_`** にします。
2. 次を実行してパスワードを入力します。画面には表示されず、ファイルや履歴にも残りません。

   ```bash
   read -rsp 'Oracle のパスワード: ' ORACLE_PWD && echo && export ORACLE_PWD
   ```

3. コンテナを起動します。初回はイメージの取得に時間がかかります。

   ```bash
   docker run -d --name factory-oracle \
     --restart unless-stopped \
     -p 127.0.0.1:1521:1521 \
     -e ORACLE_PWD \
     -v factory-oracle-data:/opt/oracle/oradata \
     container-registry.oracle.com/database/free:latest-lite
   unset ORACLE_PWD
   ```

   `127.0.0.1` を指定しているので、PC の外からは接続できません。

4. 準備完了を待ちます。`DATABASE IS READY TO USE!` が出たら `Ctrl+C` で表示を止めます(コンテナは動き続けます)。

   ```bash
   docker logs -f factory-oracle
   ```

5. **この Ubuntu のウィンドウは開いたままにします**(理由は手順 13)。

## 6. Windows から接続できることを確認する [PowerShell]

別の PowerShell を開きます。

```powershell
Test-NetConnection 127.0.0.1 -Port 1521 | Select-Object TcpTestSucceeded
```

`True` なら次へ進みます。`False` の場合は手順 15 を確認してください。

## 7. 接続設定 [PowerShell]

`factory-ontology/onprem` フォルダへ移動します。以降の PowerShell の手順は、すべてこのフォルダで実行します。

1. 設定ファイルをコピーします。

   ```powershell
   Copy-Item .env.example .env
   ```

2. `.env` を開き、次の 3 つを入れます。パスワードはすべて別の値にしてください。
   - `ORACLE_ADMIN_PASSWORD`:手順 5 で決めたパスワード
   - `FACTORY_APP_PASSWORD`:新しく決める
   - `FACTORY_RO_PASSWORD`:新しく決める

## 8. 表とデータの投入 [PowerShell]

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python simulator\oracle_db.py setup
.venv\Scripts\python simulator\oracle_db.py seed
.venv\Scripts\python simulator\oracle_db.py check
```

| コマンド | すること |
|---|---|
| `setup` | 専用の表領域 `FACTORY_DATA`、表の所有者、読み取り専用のユーザー、27 個の表を作る |
| `seed` | 全表を空にし、現在時刻までの 14 日分の模擬データを入れる |
| `check` | 読み取り専用ユーザーで件数を数え、書き込めないことを確認する |

## 9. 完了の確認

`check` の末尾が次のようになれば完了です。

```text
合計 約 29,000 行
OK: FACTORY_RO は書き込みできません
```

正確な行数は実行する日時で少し変わります。主な表の目安は次のとおりです。

| 表 | 内容 | 目安 |
|---|---|---|
| `T_SENSOR_DATA` | センサー値 | 約 25,000 行 |
| `T_DENRYOKU` | 電力 | 約 1,400 行 |
| `T_SEISAN_JISSEKI` | 生産実績 | 約 1,200 行 |
| `T_SEIZO_SHIJI` | 製造指図 | 約 150 行 |
| `T_EQP_ALM` | アラーム | 約 40 行 |

## 10. グラフの構築 [PowerShell]

`factory-ontology/graph` フォルダへ移動して実行します。Oracle の読み取り専用ユーザーでデータを読みます。AWS の費用はかかりません。

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python tools\build_graph.py
.venv\Scripts\python tools\validate.py
.venv\Scripts\python tools\ask.py --all
.venv\Scripts\python tools\viewer_server.py
```

| コマンド | すること | 確認すること |
|---|---|---|
| `build_graph.py` | Oracle を読み、`build/current.nq` を作る | 末尾が `データの問題 6 件` |
| `validate.py` | SHACL で検証する | 末尾が `適合` |
| `ask.py --all` | 全部の問いを実行する | 問い 1〜8 に答えが出る |
| `viewer_server.py` | グラフの画面を開く(`Ctrl+C` で停止) | ブラウザで工場の階層が表示される |

`vocab.py` は、使っている標準語彙の語が公式の定義に実在するかを検査します。語彙を増やしたときに実行します。

画面の使い方は次のとおりです。

- 上の検索欄に、設備コード、PLC の ID(`PRESS3`)、保全システムの ID(`E-0103`)、ロット番号を入れます。
- ノードをクリックすると、つながる先が広がります。数が多い関係は、相手の種類ごとに新しい 6 件を表示します。
- 左下で問いを選んで実行します。入力欄には模擬データの筋書きに沿った例が入っています。

## 11. クラウドへの吸い上げ [PowerShell]

AWS の共有アカウントに S3 と権限を作り、Oracle の差分を送ります。少額の費用がかかります。

### 初回の準備

`factory-ontology` フォルダで、1 回だけ実行します。`aws login` 済みの管理者で行います。

```powershell
py -3.13 -m venv cloud\.venv
cloud\.venv\Scripts\python -m pip install -r cloud\requirements.txt
cloud\.venv\Scripts\python cloud\setup_aws.py --owner kojima --notify-address you@example.com
onprem\.venv\Scripts\python -m pip install -r onprem\requirements.txt
```

`setup_aws.py` は、CA と証明書の作成、認証ヘルパーの取得(公式のハッシュを確認)、S3、権限、Lambda、通知の仕組みの作成を行います。コードを変えたときも、再度実行すると反映されます。

`you@example.com` は、実際に使うアドレスに置き換えます。送信元と既定の宛先になります。アドレスは先に SES で検証しておきます(`aws sesv2 create-email-identity --email-identity アドレス` を実行し、届いたメールのリンクを押します)。

役割ごとに別の宛先にするときは、`--recipient` を追加します。指定しない役割は既定の宛先に届きます。役割は、工場長、KPI責任者、ライン責任者、保全当番、品質保証、生産管理、管理者です。

```powershell
cloud\.venv\Scripts\python cloud\setup_aws.py --owner kojima --notify-address you@example.com --recipient 工場長=boss@example.com --recipient 保全当番=maintenance@example.com
```

宛先を変えるときも、同じコマンドを実行します。SES がサンドボックスの間は、**宛先のアドレスもすべて検証が必要です**。**証明書は 90 日で切れます。** 再度実行すると、残り 30 日を切っていれば更新されます。

秘密鍵は `cloud\.secrets` と `onprem\.secrets` に保存されます。どちらも Git には入りません。

### デモの動かし方

`onprem` フォルダで PowerShell を 2 つ開き、並べて実行します。止めるときは `Ctrl+C` です。

| 画面 | コマンド | 見せるもの |
|---|---|---|
| 左:Oracle | `.venv\Scripts\python simulator\live.py --interval 10` | アラームの発生と復帰、指図の開始と完了、各表の更新行数 |
| 右:抽出 | `.venv\Scripts\python extractor\extract.py --loop 10` | 差分だけが S3 へ送られる様子 |

`--interval` と `--loop` は秒数です。デモでは短く、確認だけなら既定の 60 秒程度で十分です。

| 状況 | 動き |
|---|---|
| 変更がない | 「差分なし」と表示し、送信しない |
| 回線が切れた | 失敗を表示して動き続け、復旧後に未送信の分を送る |
| Oracle が止まった | 失敗を表示して動き続け、再開後に続きから動く |

届いた差分は Lambda が自動でグラフへ反映します。`graph` フォルダで次を実行すると、クラウドのグラフを画面で確認できます。画面右上の更新時刻とクワッド数が、数秒ごとに変わります。

```powershell
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python tools\viewer_server.py --s3 kojima
```

### データを作り直したとき

`seed` は全データを入れ直すので、読み取り位置も消してください。次の送信が全件の送り直しになり、クラウドのグラフも作り直されます。

```powershell
.venv\Scripts\python simulator\oracle_db.py seed
.venv\Scripts\python extractor\extract.py --reset
```

### AWS の片付け

S3 の中身も含めて削除し、残存がないことを確認します。**受信データとグラフはすべて消えます。** 手元の Oracle は残ります。

```powershell
cloud\.venv\Scripts\python cloud\teardown_aws.py --owner kojima
```

SES の検証済みアドレスも消すときは、`--ses-identity アドレス` を付けます。複数あるときは繰り返します。

作り直すときは、「初回の準備」の `setup_aws.py` を実行してから、抽出の読み取り位置を消します。`--ses-identity` で消した場合は、先にアドレスを検証し直します。

```powershell
onprem\.venv\Scripts\python onprem\extractor\extract.py --reset
```

## 12. デモの進め方

事前に Oracle を起動し、データを今の日付で作り直します(手順「データを作り直したとき」)。PowerShell を 3 つとブラウザを用意します。

| 画面 | フォルダ | コマンド |
|---|---|---|
| Oracle の更新 | `onprem` | `.venv\Scripts\python simulator\live.py --interval 10` |
| 差分の送信 | `onprem` | `.venv\Scripts\python extractor\extract.py --loop 10` |
| グラフ | `graph` | `.venv\Scripts\python tools\viewer_server.py --s3 kojima` |
| 操作用 | `onprem` | 下の表のコマンドを実行する |

トラブルは、説明の流れに合わせて手で起こします。

| 見せること | コマンド | 結果 |
|---|---|---|
| 設備の故障 | `.venv\Scripts\python simulator\inject.py bearing` | プレス7号機が停止。約 10 秒で 5 役割に別々の内容のメールが届く。KPI 責任者には送らない |
| 上位への通知 | 何もしない | 5 分でライン責任者、10 分で工場長へ未対応の通知が届く |
| 対応の記録 | 保全当番のメールのリンクを開き、ボタンを押す | 上位への通知が止まる |
| 復旧 | `.venv\Scripts\python simulator\inject.py resolve` | 保全の記録が入り、グラフに反映される |
| ロットの品質問題 | `.venv\Scripts\python simulator\inject.py lot` | 品質保証、生産管理、2 ライン分の責任者、工場長に届く。保全当番には送らない |

定時レポートは、`factory-ontology` フォルダからいつでも送れます。

```powershell
cloud\.venv\Scripts\python cloud\send_report.py --owner kojima daily    # 工場長、KPI 責任者、品質保証
cloud\.venv\Scripts\python cloud\send_report.py --owner kojima weekly   # 工場長、KPI 責任者
cloud\.venv\Scripts\python cloud\send_report.py --owner kojima shift    # 各ラインの責任者
```

見せるときの注意:

- 同じロットの品質問題は、最初の 1 回だけ通知します。繰り返すときは、データを作り直します。
- 定時の自動実行は既定で止めています。動かすときは `setup_aws.py` に `--schedule` を付けます。動かしていても、データが 1 日以上届いていなければ送りません。
- 上位通知の時間は `setup_aws.py` の `--escalate-minutes 2,4` のように変えられます。
- 1 日の送信数の上限は 50 通です。

メールが Gmail の迷惑メールに入るときは、Gmail で「迷惑メールではない」にするか、件名の `[` を含むメールのフィルタを作ります。役割ごとにラベルを付けると見やすくなります。

## 13. 普段の操作

**WSL は、Ubuntu のウィンドウをすべて閉じると十数秒で止まります。** Docker をサービスとして動かしていても同じなので、Oracle を使う間は Ubuntu のウィンドウを開いたままにします。

| やりたいこと | 実行する場所 | 操作 |
|---|---|---|
| 再開する | PowerShell | `wsl -d Ubuntu-26.04` を実行し、ウィンドウを開いたままにする |
| 起動を確認する | Ubuntu | `docker logs --tail 5 factory-oracle` |
| 止める | Ubuntu | `docker stop -t 60 factory-oracle` のあと `exit` |
| データを今の日付で作り直す | PowerShell | `.venv\Scripts\python simulator\oracle_db.py seed` |

`docker stop` で止めておくと、次に WSL を開いても Oracle は自動で起動しません。その場合は Ubuntu で `docker start factory-oracle` を実行します。

## 14. 片付け

1. 表とユーザーを消します。[PowerShell]

   ```powershell
   .venv\Scripts\python simulator\oracle_db.py drop
   ```

2. Oracle を消します。[Ubuntu]

   ```bash
   docker rm -f factory-oracle
   docker volume rm factory-oracle-data
   ```

3. Ubuntu ごと不要になったら、次を実行します。[PowerShell] **この環境の中身はすべて消え、元に戻せません。** 既存の `Ubuntu-20.04` は残ります。

   ```powershell
   wsl --unregister Ubuntu-26.04
   ```

## 15. 困ったとき

| 症状 | 対処 |
|---|---|
| `wsl --list --online` に新しい版が出ない | 手順 1 の `wsl --update` を実行したか確認する |
| `Cannot connect to the Docker daemon` | Ubuntu で `sudo systemctl start docker` を実行する。繰り返すなら手順 3 の systemd を確認 |
| `permission denied ... docker.sock` | 手順 4 の開き直しができていない。`wsl --terminate Ubuntu-26.04` のあと開き直す |
| `Test-NetConnection` が `False` | Ubuntu のウィンドウが開いているか、`docker ps` で `factory-oracle` が動いているかを確認 |
| 1521 番が使用中 | `-p 127.0.0.1:1522:1521` で起動し直し、`.env` の `ORACLE_DSN` を `127.0.0.1:1522/FREEPDB1` に変更 |
| `DPY-6005` や接続拒否 | Oracle の起動中か停止中。`docker logs factory-oracle` を確認 |
| `ORA-01017` | `.env` のパスワードが違う。手順 5 の入力と一致しているか確認 |
| `ORA-12514` | 準備完了の前か、`ORACLE_DSN` のサービス名が違う |
| `setup` が途中で失敗した | `oracle_db.py drop` のあと `setup` からやり直す |
| `... は既にあります` | `setup` は実行済み。`seed` だけ実行するか、`drop` してやり直す |
| パスワードを忘れた | 手順 14 の 2 で Oracle を消し、手順 5 からやり直す |
| メールが届かない | 迷惑メールを確認する。`extract.py` が動いているか、未復旧のアラームが 6 時間以内に発生したものかを確認する |
| `AWS の設定がありません` | `cloud\setup_aws.py` が未実行 |
| 送信時に `CertificateExpired` など | 証明書が期限切れ。`cloud\setup_aws.py` を再度実行する |
