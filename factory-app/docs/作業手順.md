# 作業手順（factory-app）

工場アプリを動かして確認するまでの手順。今はステップ 2（① ナレッジグラフ・② 3D 工場）まで。
③ AI エージェントは、ステップ 3 で章を追加する。

- 設計・方針・費用・懸念点: [実現方針.md](実現方針.md)
- ナレッジグラフ（KG）・REST API の手順: [factory-kg/docs/作業手順.md](../../factory-kg/docs/作業手順.md)
- replay（工場 CSV リプレイ基盤）の手順: [factory-replay/docs/作業手順.md](../../factory-replay/docs/作業手順.md)

コマンドはすべて **PowerShell で `factory-app` フォルダから** 実行する。

| 章 | 内容 | AWS | 所要時間 |
|---|---|---|---|
| 0 | 事前準備（初回のみ） | 不要 | 5 分 |
| 1 | デモモードで動かす | 不要（費用 0 円） | 5 分 |
| 2 | AWS の KG・replay につないで動かす | 使う | 5 分 |
| 3 | ① ナレッジグラフの確認 | — | 10 分 |
| 4 | ② 3D 工場の確認 | — | 10 分 |
| 5 | テスト・画面の開発 | 不要 | 5 分 |

## 0. 事前準備（初回のみ）

- **Node.js 24 以上**（画面のビルドに使う。`node -v` で確認）
- **factory-kg の仮想環境**（`factory-kg/.venv`）。まだなければ [factory-kg の 0 章](../../factory-kg/docs/作業手順.md#0-事前準備初回のみ) で作る。アプリのサーバーはこれをそのまま使う

```powershell
cd factory-app\web
npm install          # 画面のライブラリ（バージョンは package.json で固定）
npm run build        # 型チェック + ビルド → web/dist
cd ..
```

- 画面のソース（`web/src`）を変えたら、もう一度 `npm run build` する（4 章の開発用サーバーなら不要）
- 画面のライブラリはビルドに含まれるので、動かすときにインターネット（CDN）は使わない

## 1. デモモードで動かす

AWS の環境がなくても、手元のグラフ（factory-kg の `examples/instances.sample.ttl`）とサンプル CSV で動く。
replay の値は、起動時に CSV 上の 6:00 から **60 倍速** で再生したことにして返す（1 日分を流し終えたら最初に戻る）。

```powershell
..\factory-kg\.venv\Scripts\python.exe server\app_server.py --demo     # ブラウザで http://127.0.0.1:8770/ が開く
```

- 起動時に `mode   : demo`、`アプリ : http://127.0.0.1:8770/` と表示される
- 再生の速さは `--demo-speed 720`（約 2 分で 1 日分）のように変えられる
- 再生を始める CSV 上の時刻は `--demo-start 14:25` のように変えられる（CNC-01 が 14:30 に異常停止するので、すぐに見られる）
- 止めるときはターミナルで **Ctrl+C**（`停止しました`）

## 2. AWS の KG・replay につないで動かす

factory-kg（`xcp-factorykg-<owner>`）を公開済みであること。値を見るには replay（`xcp-factory-<owner>`）も必要
（なくても動くが、値は「取得できません」と表示される）。

```powershell
aws login
$owner = "<owner>"                   # 自分の名前（例: kojima）
..\factory-kg\.venv\Scripts\python.exe server\app_server.py --owner $owner
```

- サーバーは aws login の認証情報で KG の REST API・SPARQL に署名して中継する（画面には認証情報を渡さない）
- **使い終わったら、ブラウザのタブを閉じてから Ctrl+C で止める**（表示したままだと、1 分ごとの自動更新が replay の DB を起こし続ける）

## 3. ① ナレッジグラフの確認

### 確認 3-1：画面の全体

| 場所 | 期待する結果 |
|---|---|
| 上部 | デモモードなら `DEMO` のバッジ。`replay 再生中 xx%（CSV 10/01 hh:mm）`、`KG 900 トリプル` |
| 左のグラフ | 左から サンプル工場 → サンプル工場 サイト → 製造エリア → ライン A → 設備 5 つ |
| 設備の縁の色 | CNC-01・PRESS-01 は稼働状態で色が付く（灰色 = 停止、緑 = 稼働、赤 = 異常停止） |
| 右の欄 | 工場の概要（1 ライン・5 設備・15 計測項目）と設備の一覧（稼働状態のバッジつき） |
| 下 | ③ AI エージェントの欄（ステップ 3 で実装。今は入力できない） |

### 確認 3-2：設備を選ぶ

グラフで **CNC-01** をクリックする（または右の一覧から選ぶ、検索欄に `CNC-01` と入れて Enter、`http://127.0.0.1:8770/#q=CNC-01` を開く）。

- グラフ: CNC-01 の右に計測項目 4 つ（加工数・稼働状態・主軸回転数・主軸負荷）が展開される
- 右の詳細: 稼働状態のバッジ、計測項目ごとの最新値と CSV 上の時刻、「ナレッジグラフ上の関係」（種類・名前・計測項目を持つ など）
- 関係の行（計測項目など）をクリックすると、その項目に移る

### 確認 3-3：計測項目を選ぶ（値と時系列）

詳細の **主軸負荷** をクリックする（または `http://127.0.0.1:8770/#q=CNC-01/spindle_load` を開く）。

- 最新値（大きな数字と `%`）、CSV 上の時刻と反映時刻
- 時系列グラフ（横軸は CSV 上の時刻）。右上で範囲（CSV の 1 日・直近など）を変えられる
- 「値の取得方法」: グラフ（TTL）に書かれた replay の API の URL。デモモードでは仮の `https://replay-api.invalid/…`
- **PRESS-01 の稼働状態** を選ぶと、値が `稼働（1）` のようにコード表の意味で表示され、時系列は階段状になる

### 確認 3-4：検索・絞り込み・SPARQL・自動更新・テーマ

| 操作 | 期待する結果 |
|---|---|
| 検索欄に `コンプレッサ` → Enter | COMP-01 が選ばれる |
| 分類を `CNC 加工機` | CNC-01 以外の設備が薄くなる |
| 「全体」ボタン（またはグラフの空白をダブルクリック） | グラフ全体が収まる |
| 下の「SPARQL を直接実行する」を開いて「実行」 | 設備 ID・名前・分類の表（5 行）。更新文（INSERT など）はエラーになる |
| 画面を表示したままにする | 1 分ごとに上部の %・設備の縁の色・詳細の値が変わる（別のタブに切り替えている間は止まる） |
| 右上の太陽／月のボタン | ライト・ダークのテーマが切り替わる |

## 4. ② 3D 工場の確認

「② 3D 工場」のタブを開く（または `http://127.0.0.1:8770/#tab=3d`。`#tab=3d&q=CNC-01` なら CNC-01 を選んだ状態で開く）。
設備の位置・大きさはナレッジグラフの配置（factory-kg の `ontology/layout.ttl`）、状態と値は replay の最新値から作っている。

### 確認 4-1：工場の全体

| 場所 | 期待する結果 |
|---|---|
| 建屋 | コンクリートの床（目地）、北・東・西の壁と高窓、柱（足元は黄色）、天井照明。視点を屋根より下げると梁も見える |
| 床 | ライン A の区画（黄色の線）と `LINE-A  ライン A` の文字、その南側の安全通路（緑、黄黒の縁）、南西の角に `製造エリア` |
| 設備 | 西から プレス機（青いフレーム）→ 搬送コンベア → CNC 加工機（窓付きの筐体）。南の壁際にエアコンプレッサ（赤いタンク）、中央の柱に環境センサ |
| ラベル | 設備の上に ID・名前・主な値（例: `CNC-01 主軸負荷 58.3 %`）と状態 |
| 左下 | 信号灯の凡例と台数（稼働・異常停止・停止） |

### 確認 4-2：状態と動き（データ連動）

| 設備 | 期待する結果 |
|---|---|
| 積層信号灯（環境センサ以外） | 稼働 = 緑、異常停止 = 赤の点滅、停止 = 消灯。床の周りも同じ色で薄く光る |
| プレス機 | 稼働中はラムが上下する（ショット数が多いほど速い） |
| 搬送コンベア | 搬送速度に合わせてベルトとワークが東へ流れる。速度 0 なら止まる |
| CNC 加工機 | 稼働中は窓の中が光り（主軸負荷が高いほど明るい）、主軸が回る。異常停止では窓が赤くなる |
| エアコンプレッサ | 圧力計の針が吐出圧力（0〜1 MPa）を指す。消費電力 10 kW 以上で稼働（ファンが回る） |
| 環境センサ | 表示の色が温度で変わる（18 ℃ 未満 = 青、28 ℃ 以下 = 緑、それより上 = 橙） |

- 稼働状態（status）を持たない設備は、値から判定している（コンベア = 速度が 0 より大きい、コンプレッサ = 消費電力 10 kW 以上）
- 異常停止を見るには、デモを `--demo-start 14:25` で起動する（約 5 秒後に CNC-01 が赤の点滅になる。1 分ごとの自動更新か「更新」で反映）

### 確認 4-3：操作・連動・表示の設定

| 操作 | 期待する結果 |
|---|---|
| ドラッグ・ホイール・右ドラッグ | 回転・拡大・移動 |
| 設備をクリック（またはラベルをクリック） | 水色の枠で囲まれ、視点が寄り、右の詳細にその設備が出る。詳細に「配置（② 3D 工場）」の位置・大きさ |
| ① で設備を選んでから ② を開く | ② でもその設備が選ばれ、視点が寄る |
| 「全体」「ラインに沿って」「選択中の設備」 | それぞれの視点へなめらかに移る |
| 「昼間 / 夜間」 | 夜間は照明を落とす（天井照明は 1 列だけ、信号灯・画面の光が目立つ） |
| 「高画質 / 標準」 | 高画質は影・光のにじみ（ブルーム）・環境光の遮蔽あり。PC が重いときは標準に |
| 「ラベルあり / なし」 | 設備の上のラベルを出す・隠す |

- 表示の設定（昼夜・画質・ラベル）は、このブラウザに覚えておく
- ③ のエージェントが挙げた設備は琥珀色の点滅の枠で強調される（ステップ 3 で確認）

## 5. テスト・画面の開発

```powershell
..\factory-kg\.venv\Scripts\python.exe -m unittest discover -s tests -v    # サーバー・デモモードのテスト（AWS 不要）
cd web; npm run typecheck; cd ..                                            # 画面の型チェック
```

画面を直しながら確認するときは、サーバー（1 章か 2 章）を動かしたまま、別のターミナルで開発用サーバーを使う。

```powershell
cd web
npm run dev          # http://localhost:5173/ 。ソースを保存すると画面がすぐ変わる。/api はサーバー（8770）へ中継
```

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `画面がビルドされていません` | `web` フォルダで `npm install` と `npm run build` |
| `--owner を指定するか、--demo で起動してください` | どちらかを付けて起動する |
| 画面が真っ白 | ブラウザの開発者ツール（F12）のコンソールのエラーを確認。`npm run build` をやり直す |
| `起動に失敗しました` のエラーが右下に出る | サーバーのターミナルのエラーを確認（AWS なら `aws login` の期限切れ、KG の未公開など） |
| ポート 8770 が使用中 | `--port 8771` のように変える |
